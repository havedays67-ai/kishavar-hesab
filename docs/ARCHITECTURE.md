# معماری کشاورزحساب

## ۱) هدف طراحی
- حسابداری درست برای **کشاورز غیرحسابدار** (زبان ساده + هوش دستیار).
- اجرای سبک روی **اندروید با ۶ گیگ رم** (حداقل JS، رندر سروری).
- داده تمیز و قابل اتکا (قیدهای دیتابیس، مبالغ صحیح، سیدر اتمیک).
- هوش **محدوده‌دار**: فقط این نرم‌افزار و حسابداری کشاورزی.

## ۲) لایه‌ها
| لایه | فناوری | مسئولیت |
|---|---|---|
| UI | Next.js App Router + Tailwind v4 | RTL، موبایل‌محور، کامپوننت‌های سبک، SVG chart |
| Mutation | Server Actions (`src/app/actions.ts`) | اعتبارسنجی، نرمال‌سازی ارقام فارسی، نوشتن در DB |
| Read | `src/lib/data.ts` | کوئری‌های Drizzle + تجمیع برای داشبورد/گزارش/هوش |
| AI | `src/lib/ai/*` | NLU فارسی، پرکردن اسلات، ابزارهای امن، RAG، گزارش‌ساز، LLM اختیاری |
| DB | PostgreSQL + Drizzle | ۱۷ جدول، قیدها و ایندکس‌ها |
| Mobile | Capacitor (minSdk 26) | WebView بومی + صفحه راه‌اندازی آدرس سرور |

## ۳) جریان ثبت با دستیار
```
کاربر: «۲۵ میلیون کود اوره برای زمین شمالی خریدم نسیه»
   │
   ├─ NLU: قصد = add_expense، مبلغ = 25,000,000، دسته = کود و سم،
   │       زمین = زمین شمالی، روش = اعتباری
   ├─ اسلات‌های الزامی: amount ✓ ، category ✓  → تکمیل
   ├─ پیش‌نمایش + درخواست تأیید  (chat_threads.state.pending)
   ▼
کاربر: «تأیید»
   ├─ executePending() → INSERT transactions (source='assistant')
   ├─ refreshInsights() → assistant_notes
   └─ پاسخ موفقیت + لینک صفحه دفتر عملیات
```
اگر اسلات الزامی ناقص باشد، موتور به‌جای حدس زدن، **سؤال دقیق** می‌پرسد و پاسخ را در همان پیش‌نویس ادغام می‌کند. اگر کاربر موضوع را عوض کند، پیش‌نویس قبلی حفظ می‌شود تا اطلاعات از دست نرود.

## ۴) امنیت و محدوده دسترسی
- حالت `support` هیچ تابع نوشتنی صدا نمی‌زند؛ فقط خواندن + پایگاه دانش.
- حالت `assistant` فقط از طریق توابع بسته و پارامتری (`executePending`) می‌نویسد؛ هیچ SQL آزاد از متن کاربر ساخته نمی‌شود.
- کلیدهای API فقط سمت سرور خوانده می‌شوند (`process.env`)، هرگز به کلاینت نمی‌روند.
- مدل زبانی فقط «بیان» پاسخ را بهبود می‌دهد و ورودی آن شامل پاسخ معتبر موتور محلی است.
- محافظ موضوعی: موضوعات بیربط رد می‌شوند و پیشنهاد موضوع مجاز داده می‌شود.

## ۵) مدل داده و کیفیت
- `bigint` برای تومان، `double precision` برای مقدار فیزیکی، `date` برای تاریخ.
- قید `CHECK` برای مبلغ نامنفی، enumهای متنی، وضعیت چک و برداشت.
- ایندکس روی `transactions.date/land_id/crop_id`، `cheques.due_date`، `debts.paid`، `crops.land_id`.
- سیدر با `pg_advisory_xact_lock` و کلید `settings.seeded` یک‌بار اجرا می‌شود.
- داده نمونه شامل ۴ زمین، ۵ کشت، ~۳۰ تراکنش واقعی، ۸ قلم انبار، ۶ دستمزد، ۴ ماشین، ۶ بدهی/طلب، ۴ چک و ۱۵ مقاله آموزشی است.

## ۶) انتخاب‌های آگاهانه
- **بدون Chart.js**: نمودارها SVG سرورساید؛ صفر کیلوبایت JS اضافه.
- **بدون ORM دوم/State Manager**: Server Actions + server components.
- **بدون ذخیره کلید در کلاینت**: چت از مسیر `/api/assistant/chat` عبور می‌کند.
- **Capacitor به‌جای React Native**: همان کد وب، بدون بازنویسی؛ minSdk 26.

## ۷) تست دستی پیشنهادی
1. `/transactions` ← ثبت هزینه با ارقام فارسی «۵٬۰۰۰٬۰۰۰» ← بررسی نمایش ۵ میلیون.
2. `/assistant` ← حالت دستیار ← «برای فروشگاه نهاده ۴۴ میلیون چک ۱۰ روز بعد بنویس» ← «تأیید» ← `/finance`.
3. `/assistant` ← حالت پشتیبان ← «بهای تمام‌شده چطور محاسبه می‌شود؟» ← پاسخ آموزشی + لینک پایگاه دانش.
4. `/assistant` ← «نتیجه فوتبال دیشب» ← رد محترمانه و پیشنهاد موضوع مجاز.
5. `/inventory` ← خروج بیش از موجودی ← جلوگیری و پیام خطا.

# بنچمارک واقعی لایهٔ فهم سریع و ساختار ایندکس

> این سند فقط عددهای **اندازه‌گیری‌شده** را دارد. چیزی که اندازه‌گیری نشده،
> عدد ندارد و صریحاً «اندازه‌گیری نشده» نوشته شده است.

## محیط اندازه‌گیری

| مورد | مقدار |
|---|---|
| اجراکننده | `npx tsx tools/build_pack/bench-index.ts` |
| محیط | Node v22.23.4 · linux/x64 · سندباکس CI/توسعه |
| روی گوشی اندروید | **اندازه‌گیری نشده** (نیازمند Instrumented Test روی دستگاه ۶GB) |
| کلیدهای بسته | ۸٬۰۴۲ کلید یکتا (بسته ۲۸۳٬۵۰۰ بایت) |
| پرس‌وجو | ۴۰٬۰۰۰ مثبت + ۴۰٬۰۰۰ منفی (کلید تصادفیِ قطعاً نبوده) |

## ایندکس‌ها (میانگین میکروثانیه بر پرس‌وجو، در همان اجرا)

| ساختار | hit (µs) | miss (µs) | p95 miss (µs) | بایت بر کلید | حکم |
|---|---|---|---|---|---|
| sorted-u32 + binary (فرمت v1) | 0.144 | 0.163 | 0.196 | **4.0** | کم‌حجم، ولی هر miss چند پرش حافظه |
| **sorted-u32 + bloom (فرمت v2، فعلی)** | 0.167 | **0.082** | **0.109** | **5.25** (۱.۲۵ بایت bloom) | **بهترین توازن حجم/زمان** |
| open-address u32 hash table (شبیه SQLite، mmap) | 0.115 | 0.107 | 0.187 | 16.3 | hit بهتر، ۳ برابر حافظه |
| `Map<number,number>` (heap) | 0.118 | 0.100 | 0.128 | 64.3 | RAM Too زیاد برای بستهٔ اختیاری |
| sorted strings + binary (پروکسی FST) | 0.341 | 0.427 | 0.620 | 11.74 | کندتر؛ FST واقعی پیاده‌سازی نشده |
| bloom-only (پیش‌فیلتر) | 0.106 | 0.084 | 0.110 | 1.25 | تشخیص «قطعاً نیست» |

**نتیجه:** فرمت v2 (bloom + جستجوی دودویی روی آرایهٔ مرتب) انتخاب شد؛
زمان miss حدود **۵۰٪** کمتر و حافظهٔ اضافی فقط **۱.۲۵ بایت بر کلید** است.
`Map` روی hit کمی سریع‌تر است، اما ۱۲ برابر حافظه می‌خواهد و برای گوشی ۶ گیگ
با بستهٔ اختیاری ۵۰MB به‌صرفه نیست. مقایسه با FST واقعی و اندازه‌گیری روی
ART انجام نشده است.

## Bloom filter

| مورد | مقدار |
|---|---|
| بیت بر کلید | 10 (k=7) |
| نرخ خطای تخمینی (فرمول) | 0.8192% |
| نرخ خطای **اندازه‌گیری‌شده** روی ۲٬۰۰۰ کلید ناشناخته | **0.85%** |
| false-negative | **صفر** (تست خودکار: همهٔ کلیدهای بسته پیدا می‌شوند) |
| ذخیره‌شده | فقط بیت هش کلیدِ ماسک‌شده — نه متن، نه مبلغ |

## اثر روی لایهٔ فهم سریع (eval_report.json)

| سنجه | قبل | بعد |
|---|---|---|
| دقت intent (۲۴۰ نمونهٔ سختِ دیده‌نشده) | 97.5% | **99.58%** |
| slot exact-match | 56.25% | **81.25%** |
| slot precision | 51.34% | **77.27%** |
| نرخ توضیح‌خواهی (clarify) | 1.67% | 0.42% |
| p95 پاسخ (Node، ۲۴۰ نمونه) | 0.399ms | 0.719ms |

**صداقت:** بهبود دقت از رفع شکاف‌های واژگانی عمومی (پسوند صرفی، برگشت پول،
ابهام خرید/هزینه، خروج انبار) آمده، ولی مجموعهٔ آزمون ترکیبی است؛ برای عدد
قابل‌اعتماد روی کاربر واقعی به یک مجموعهٔ آزمون انسانیِ مستقل نیاز است.
افزایش p95 هم به‌خاطر اضافه‌شدن ثبت سنجه و نوسان اندازه‌گیری Node است؛
روی گوشی اندازه‌گیری نشده است.

## نکتهٔ پروفایل

پیش از بهینه‌سازی، مسیر داغ سنجیده شد: Router متن را نرمال می‌کرد و بعد
`pack.lookup(text)` **دوباره** نرمال‌سازی می‌کرد؛ همین کار حدود ۲۰µs برای
هر جمله هزینه داشت. اکنون هش یک‌بار محاسبه و `lookupByHash` /
`mightContainHash` استفاده می‌شود (بررسی bloom با هش آماده: ۰.۱۵µs برای هر جمله).

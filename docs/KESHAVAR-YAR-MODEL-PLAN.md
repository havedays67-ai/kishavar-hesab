# نقشهٔ «کشاورزیار» — دستیار باهوش، کش‌دار و بهینه برای گوشی

> وضعیت سند: پیشنهاد فنی برای نسخهٔ بعد (جایگزین مدل زبانی همراه APK نیست؛ نگاشت مسیر است).
> اصل حاکم: **عدد و سند را مدل نمی‌سازد.** مدل فقط می‌فهمد، توضیح می‌دهد و پیشنهاد می‌دهد؛
> هر عدد از موتور قطعی روی همان دستگاه می‌آید.

---

## ۱) وضعیت واقعی امروز (بر اساس کد همین مخزن)

| لایه | فایل | وضعیت |
|---|---|---|
| موتور ریاضی قطعی (BigInt/کسر) | `app-v2/src/lib/ai/math-engine.ts` | فعال، بدون float و بدون eval |
| نرمال‌ساز فارسی | `app-v2/src/lib/nlu/normalizer.ts` | فعال (ي/ك، اعداد، نیم‌فاصله، ماسک اعداد) |
| قواعد قطعی | `app-v2/src/lib/nlu/rules.ts` | فعال؛ ۲۸+ قصد با threshold ۰٫۶۲ |
| بستهٔ پاسخ + Bloom | `app-v2/src/lib/nlu/pack.ts` | فعال؛ ایندکس هش دودویی، بدون JSON در مسیر داغ |
| کش یادگیری موضعی | `app-v2/src/lib/nlu/learned-cache.ts` | فعال؛ LRU، بدون نگه‌داشتن هیچ عددی |
| مغز CPU | `app-v2/src/lib/nlu/cpu-brain.ts` | Naive Bayes با وزن int8، حدود ۱۰۰KB |
| بازیاب معنایی | `app-v2/src/lib/nlu/retriever.ts` | TF-IDF محلی، فقط حالت پشتیبان |
| مدل زبانی | `app-v2/src/lib/nlu/model.ts` | **وزن ندارد**؛ جای اتصال llama.cpp/GGUF آماده است |
| دانشنامه + بانک Q/A | `app-v2/src/lib/ai/knowledge*.ts` | فعال، با منبع و نسخه |

یعنی ستون‌های «سریع، ارزان، قابل اعتماد» ساخته شده‌اند. آنچه «باهوش‌تر» را می‌سازد
دو چیز است: **فهم زبان آزاد** و **استدلال چندمرحله‌ای کنترل‌شده**. هیچ‌کدام با
بزرگ‌تر کردن یک مدل داخل APK حل نمی‌شود.

## ۲) چرا یک LLM بزرگ داخل APK پاسخ درست نیست

| گزینه | حجم تقریبی | RAM هنگام اجرا | تجربه روی گوشی ۴–۶GB |
|---|---|---|---|
| مدل ۰٫۵B با ۴بیت | ۳۰۰–۴۰۰MB | ۶۰۰MB–۱GB | کند، گرم شدن، خطر kill شدن WebView |
| مدل ۱–۱٫۵B با ۴بیت | ۷۰۰MB–۱GB | ۱٫۲–۲GB | فقط گوشی‌های رده‌بالا |
| مدل ۳B+ | ۲GB+ | ۳GB+ | عملاً نامناسب |

نتیجه: **مدل زبانی نباید داخل APK پایه باشد.** باید:
1. به‌صورت اختیاری دانلود شود (بستهٔ استدلال، ۱۵۰–۴۰۰MB)،
2. فقط وقتی لایه‌های سریع به نتیجه نرسیدند اجرا شود،
3. خروجی‌اش همیشه از «دروازهٔ اعتبارسنجی» بگذرد.

## ۳) معماری پیشنهادی: «دست‌های قطعی، مغز کوچک، مشاور اختیاری»

```
پیام کاربر
   │
   ▼
[L0] موتور ریاضی + نرمال‌ساز            ← هیچ مدلی؛ همیشه و همه‌جا
   │
   ▼
[L1] قواعد قطعی (Rules)                 ← سریع‌ترین، قابلیت توضیح
   │
   ▼
[L2] کش سه‌سطحی  (پیشنهاد ارتقا)
      ۱) هش دقیق جملهٔ ماسک‌شده (موجود)
      ۲) کش قالب/اسلات: «# میلیون # خریدم» → قالب
      ۳) کش معنایی: بردار جمله + cosine ≥ آستانه
   │
   ▼
[L3] مغز CPU (دسته‌بند int8)            ← intent + slots، بدون تولید متن
   │
   ▼
[L4] بازیاب دانش (BM25 + بردار کوچک)    ← پاسخ با منبع، نه از حافظهٔ مدل
   │
   ▼
[L5] «مشاور» اختیاری (LLM کوچک دانلودی) ← فقط برای فهم/توضیح/گفت‌وگو
   │
   ▼
[L6] دروازهٔ اعتبارسنجی (Verifier)      ← JSON schema، بازبینی عدد، واحد، تاریخ، منبع
   │
   ▼
پاسخ + اقدام‌های قابل اجرا (پیش‌نویس سند، نه ثبت خودکار)
```

### قانون طلایی استدلال درست
مدل «استدلال آزاد» (CoT) نمی‌نویسد که کاربر بخواند؛ **ابزار صدا می‌زند**:

```json
{"tool":"ledger.receivable","args":{"period":"this_season"}}
{"tool":"math.percent","args":{"percent":18,"base":25000000}}
{"tool":"knowledge.search","args":{"query":"افت رطوبت گندم"}}
```

سپس:
- نتیجهٔ ابزار با موتور قطعی محاسبه می‌شود (نه با مدل)،
- مدل فقط **جمع‌بندی زبانی** می‌کند،
- Verifier بررسی می‌کند: عدد پاسخ ∈ خروجی ابزار؟ واحد درست؟ تاریخ شمسی معتبر؟
  منبع دارد؟ اگر نه → پاسخ رد و به لایهٔ قبل برمی‌گردد.

این همان چیزی است که «هوش» را از «توهم» جدا می‌کند.

## ۴) کش: سه سطح، نه یکی

| سطح | کلید | مزیت | هزینه |
|---|---|---|---|
| C1 هش دقیق | جملهٔ نرمال‌شده با اعداد ماسک‌شده (موجود) | O(1)، صفر خطا | فقط تکرار عین جمله |
| C2 کش قالب | قالب جمله + نوع اسلات | پوشش «۲۵ میلیون کود خریدم» و «۳۰ میلیون کود خریدم» با یک رکورد | باید قالب‌ساز دقیق باشد |
| C3 کش معنایی | بردار جمله (int8) + cosine | پوشش paraphrase («پول کود چقدر دادم») | ۲۰–۵۰MB مدل تعبیه + محاسبه |

سیاست‌ها:
- آستانهٔ C3 محافظه‌کارانه (مثلاً ۰٫۹۲)؛ زیر آن به مغز/مشاور برو.
- TTL برای پاسخ‌های وابسته به دفتر (مثلاً ۲۴ ساعت) یا بهتر: **هر پاسخ داده‌ای کش نشود**؛
  فقط intent/slots کش شود (قاعدهٔ فعلی درست است).
- کش منفی برای موضوعات خارج از حوزه (بدون تکرار هزینه).
- LRU + سقف حجم + دکمهٔ «پاک کردن حافظه» (بخشی از حریم خصوصی).

نکتهٔ مهم: در پروژه الان **درست** عمل شده که هیچ عدد مالی در کش نمی‌رود.
این را حفظ کنید؛ کش فقط «فهم» را ذخیره می‌کند نه «داده» را.

## ۵) مدل‌های پیشنهادی (۲۰۲۵–۲۰۲۶) برای گوشی

> اعداد تقریبی و برای مقایسه‌اند؛ قبل از انتخاب، بنچمارک روی گوشی هدف لازم است.

**دسته‌بند/فهم (L3) — داخل APK، زیر ۱۰MB:**
- همین Naive Bayes int8 فعلی را نگه دارید (سریع، قابل ممیزی).
- ارتقا: **DistilBERT فارسی چندزبانه** یا یک MLP روی ویژگی‌های واژگانی/نویسه‌ای
  (char n-gram) با کوانتیزهٔ int8؛ هدف: intent ≥ ۹۷٪ روی تست انسانی، حجم < ۸MB.
- گزینهٔ سبک‌تر و دقیق‌تر: **Linear/LogReg + char-ngram TF-IDF** — در عمل برای فارسی
  محاوره‌ای بسیار قوی و تقریباً صفر مصرف.

**تعبیهٔ معنایی (C3) — اختیاری، ۲۰–۵۰MB:**
- `multilingual-e5-small` یا `paraphrase-multilingual-MiniLM` با کوانتیزهٔ int8.
- اگر مدل فارسی اختصاصی پیدا کردید، اولویت دارد؛ وگرنه چندزبانه کافی است.

**مشاور/LLM (L5) — دانلودی، اختیاری:**
- کلاس ۰٫۵–۰٫۸B با ۴بیت (مثلاً Qwen3-0.6B، Gemma-3-270M، SmolLM3-360M، LFM2-350M).
- اجرا با llama.cpp (GGUF) از طریق پلی که در `model.ts` آماده است.
- فقط برای: بازنویسی محترمانه، توضیح گزارش، پرسش‌های چندمرحله‌ای، پیشنهاد تصمیم.
- هرگز برای: محاسبه، تاریخ، مبلغ، حکم حقوقی قطعی.

**مدل «استدلال» بزرگ‌تر — فقط سرور/دسکتاپ برای آموزش، نه گوشی:**
- به‌عنوان «معلم» برای تولید داده و distill به مدل کوچک استفاده شود
  (همین مسیر Kaggle/LoRA که در `training/` دارید).

## ۶) بودجهٔ گوشی (هدف قابل سنجش)

| سنجه | هدف |
|---|---|
| پاسخ لایه‌های L0–L3 | p95 < ۳۰ms |
| پاسخ با مشاور L5 | p95 < ۲٫۵s (گوشی میان‌رده) |
| RAM پایه | < ۸۰MB |
| RAM با مشاور | < ۷۰۰MB و آزادسازی فوری پس از پاسخ |
| رشد APK پایه | < ۵MB (فقط کد و کش) |
| بستهٔ اختیاری مشاور | ۱۵۰–۴۰۰MB، قابل حذف |
| باتری | مشاور فقط با تأیید کاربر یا حالت «تحلیل عمیق» |

## ۷) آموزش و سنجش (بدون توهم عدد)

1. **دادهٔ طلایی انسانی:** ۵۰۰–۱۰۰۰ جملهٔ واقعی کشاورز (نه تولیدی) برای تست؛
   تست فعلی مصنوعی است و ادعای ۱۰۰٪ روی آن، معیار خوبی نیست.
2. **Distillation:** معلم بزرگ → برچسب intent/slots → مدل کوچک.
3. **DPO/ترجیح:** برای «وقتی نمی‌داند، نمی‌سازد» و «سؤال روشن‌کننده می‌پرسد».
4. **دروازه‌های سخت در CI:**
   - intent روی تست انسانی ≥ ۹۵٪
   - نرخ «عددی که در دفتر نیست» = ۰
   - نرخ JSON نامعتبر مدل = ۰ (اعتبارسنج فعلی)
   - هیچ پاسخ حقوقی بدون منبع = ۰
5. **ارزیابی A/B روی گوشی:** زمان، RAM، رضایت.

---

## ۸) مسیر اجرا (فازبندی کم‌ریسک)

- **فاز A (همین حالا):** تثبیت L0–L3 + رفع باگ‌های مسیردهی (انجام شد) + تست‌های رگرسیون.
- **فاز B:** کش قالب (C2) + کش معنایی (C3) با مدل تعبیهٔ کوچک؛ بدون تغییر UI.
- **فاز C:** اتصال مشاور دانلودی با tool-calling + Verifier؛ پیش‌فرض خاموش.
- **فاز D:** distill مدل کوچک از معلم و جایگزینی تدریجی مغز CPU.

---

## ۹) جمع‌بندی یک‌خطی

> «هوش» را از مدل بزرگ نگیرید؛ از **ترکیب موتور قطعی + کش چندسطحی + دسته‌بند کوچک +
> دانشنامهٔ منبع‌دار** بگیرید و مدل زبانی را به‌عنوان **مشاور اختیاری با ابزار و بازبین**
> اضافه کنید. این هم روی گوشی ۴GB اجرا می‌شود، هم عدد اشتباه نمی‌دهد.

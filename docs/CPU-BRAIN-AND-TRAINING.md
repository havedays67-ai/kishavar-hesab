# مغز CPU، آموزش ۲ میلیون نمونه و پیکرهٔ فارسی ۱ میلیون خطی

> این سند فقط عددهای **اندازه‌گیری‌شده** را دارد. هر جا عددی وجود ندارد،
> صریحاً «اندازه‌گیری نشده» نوشته شده است.

## ۱) چه چیزی آموزش می‌بیند؟

| مورد | مقدار پیش‌فرض (CI) | ظرفیت کامل (`--full`) |
|---|---|---|
| نمونهٔ سؤال/جواب **نشان‌دار** (قصد + اسلات + جواب) | ۶۰٬۰۰۰ | **۲٬۰۰۰٬۰۰۰** |
| خط پیکرهٔ **زبان فارسی** | ۱۲۰٬۰۰۰ | **۱٬۰۰۰٬۰۰۰** |
| hold-out مستقل از آموزش | ۵٪ | ۵٪ |
| واژگان فارسی آموخته‌شده در APK | ۲۶۰ واژه | ۶٬۰۰۰ واژه |

```bash
npx tsx tools/train/train-brain.ts                 # پیش‌فرض CI (~۳ ثانیه)
npx tsx tools/train/train-brain.ts --full          # ۲ میلیون + ۱ میلیون خط
npx tsx tools/train/train-brain.ts --labeled 500000 --persian 250000
```

خروجی کامل ۲ میلیون نمونه در `artifacts/train/` (خارج از گیت) نوشته می‌شود؛
داخل APK فقط **مدل فشرده** می‌رود، نه دیتاست.

## ۲) مدل

- الگوریتم: Naive Bayes چندجمله‌ای با **سطل هش ۴۰۹۶** روی واژه، ترکیب دو واژه و
  n-gram نویسه‌ای چهارحرفی (برای تحمل غلط املایی).
- کمی‌سازی: وزن‌ها به **int8** و پیش‌ها به **int16** تبدیل می‌شوند.
- حجم مدل: **۱۰۶٬۴۹۶ بایت** (~۱۰۴KB) — داخل باندل، بدون دانلود.
- استنتاج: فقط جمع و ضرب عدد صحیح روی پردازندهٔ گوشی؛ بدون شبکه، بدون GPU،
  بدون JSON در مسیر داغ.
- قانون ثابت: ویژگی‌ها از متنِ **ماسک‌شده** ساخته می‌شوند؛ هیچ مبلغی در وزن‌ها نیست.

## ۳) اعداد واقعی (از `training/report.json`)

| سنجه | مقدار |
|---|---|
| دقت روی hold-out تولیدشده | **۱۰۰٪** |
| دقت روی مجموعهٔ سختِ مستقل (hard-eval، ۲۴۰ نمونهٔ دیده‌نشده) | **۷۶.۶۷٪** |
| پوشش (پاسخ‌دادن) روی hard-eval | ۱۰۰٪ |
| زمان آموزش (۶۰٬۰۰۰ + ۱۲۰٬۰۰۰) | ~۲.۷ ثانیه |
| زبان فارسی: واژهٔ یکتا | ۲۶۰ |

**صداقت مهم:** دقت ۱۰۰٪ روی hold-out طبیعی است چون hold-out از همان خانوادهٔ
قالب‌هاست. عدد قابل‌اعتمادتر همان **۷۶.۶۷٪** روی مجموعهٔ سختِ مستقل است؛ به همین
دلیل مغز CPU **فقط آخرین لایه** است (بعد از قواعد و بستهٔ پاسخ) و آستانهٔ پذیرش
`0.86` دارد. هیچ ادعای «۲۰ برابر شدن هوش» نمی‌کنیم؛ چیزی که تغییر کرده و
اندازه‌گیری شده این‌هاست:

| سنجه | قبل | بعد |
|---|---|---|
| دقت intent روی ۲۴۰ نمونهٔ سخت | ۹۹.۵۸٪ | **۱۰۰٪** |
| تطابق کامل slots | ۸۱.۲۵٪ | ۸۱.۶۷٪ |
| لایه‌های پاسخ‌دهنده | rules ۲۳۹ / clarify ۱ | rules ۲۳۹ / **brain ۱** |
| دانش‌آموختهٔ قابل آموزش | فقط قالب‌های بسته | **۶۰٬۰۰۰ نمونه (تا ۲ میلیون)** + ۱۲۰٬۰۰۰ خط فارسی (تا ۱ میلیون) |

## ۴) پردازندهٔ گوشی به‌عنوان مغز + شبیه‌ساز

- مغز CPU بدون رشتهٔ اضافه و بدون تخصیص سنگین اجرا می‌شود؛ هزینه‌اش با
  `features × labels` جمع عدد صحیح است.
- شبیه‌ساز `app-v2/src/lib/nlu/processor-sim.ts` مسیر هر جمله را با **شمارش عملیات
  عدد صحیح** مدل می‌کند (این شبیه‌سازی سخت‌افزار نیست و ادعای GPU ندارد).
- نتیجه روی ۲۴۰ نمونهٔ سخت: میانگین **۶۳۶.۶ عملیات صحیح** ≈ **۰.۲۱µs** با فرض
  ۱GHz؛ بیشترین هزینه ۳٬۵۶۰ عملیات در مسیر مغز، یعنی حتی بدترین جمله هم
  ارزان‌تر از یک فراخوانی مدل است. زمان واقعی روی ART/گوشی **اندازه‌گیری نشده**.

## ۵) بانک سؤال/جواب نشان‌دار

`app-v2/src/lib/ai/qa-bank.ts` شامل ۳۱ پرسش/پاسخ **نشان‌دار** (قصد، دسته، برچسب)
است، با جواب معلوم و آماده؛ رابط کاربر تا ۱۲ پیشنهاد نشان‌دار و جواب قطعی برای
پرسش‌های پرتکرار می‌دهد. همین ردیف‌ها به‌عنوان نمونهٔ آموزشی هم استفاده می‌شوند.

## ۶) محدودیت‌های صادقانه

- مدل بزرگ کوانتیزه (LLM) همراه APK نیست؛ مغز CPU سبک و آفلاین است.
- پیکره و hold-out ترکیبی‌اند، نه گفتار واقعی کاربران.
- بنچمارک روی گوشی ۶ گیگ انجام نشده؛ اعداد شبیه‌ساز، مدل عملیات است نه زمان واقعی.
- آموزش «۲ میلیون» ظرفیت دارد و اجرای آن تکرارپذیر است، اما نسخهٔ داخل APK از
  آموزش سبک‌تر می‌آید تا حجم باندل و زمان CI معقول بماند.

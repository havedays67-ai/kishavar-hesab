# لایهٔ فهم سریع کشاورزحساب (نسخه ۱.۰.۰)

## ترتیب ثابت پردازش

1. **Normalizer** — ارقام فارسی/عربی، ی/ک، نیم‌فاصله، واحدها (تن، کیلوگرم،
   هکتار، سبد، کیسه…)، اعداد حرفی («دو میلیون و پانصد»)، ماسک اعداد.
2. **Rule Engine** — ۳۰ قاعدهٔ قطعی با واژه‌نامهٔ کشاورزی و آستانهٔ اطمینان
   `RULE_THRESHOLD = 0.62`. نتیجه: `intent + slots + confidence` بدون هیچ مبلغ.
3. **Learned Cache** — نگاشت جملهٔ ماسک‌شده ← intent/slots، سقف LRU، محلی و
   قابل پاک‌سازی؛ فقط پس از تأیید کاربر نوشته می‌شود. ثبتِ مقدار دارای رقم رد می‌شود.
4. **Answer Pack** — فایل دودویی `KHPK` v2: Bloom filter + رکوردهای مرتب
   (`hash → offset/len`) + blob برچسب‌ها. کلید از جملهٔ نرمال‌شدهٔ ماسک‌شده
   ساخته می‌شود؛ نه متن خام، نه مبلغ.
5. **Support Retriever** — TF-IDF سبک، فقط در حالت «پشتیبان»؛ پاسخ‌های گزارشی
   هیچ‌وقت از این لایه نمی‌آیند.
6. **Model Fallback** — آخرین راه؛ در این نسخه مدلی همراه APK نیست، پس Router
   صادقانه سؤال شفاف می‌پرسد (`clarify`) و حدس نمی‌زند.

قانون ثابت: **محاسبات مالی و گزارش‌ها همیشه از موتور قطعی** می‌آیند؛ لایهٔ
فهم فقط intent/slots می‌دهد. تست خودکار `storesTextOrMoney` و «هیچ عددی در
بسته/کش» این قانون را نگه می‌دارد.

## Bloom filter (فایل `app-v2/src/lib/nlu/bloom.ts`)

- پیش از هر جستجوی بسته، یک بیت‌آرایه با ۱۰ بیت بر کلید و ۷ هش بررسی می‌شود.
- هیچ false-negative ندارد (تست خودکار)؛ فقط اگر «شاید باشد» جستجوی دودویی
  انجام می‌شود. نرخ مثبت کاذب اندازه‌گیری‌شده: **۰.۸۵٪**.
- فایل بسته v2 سازگار با خواندن بسته‌های v1 است.

## محدودیت‌های صادقانه

- مجموعهٔ سخت **ترکیبی** است، نه گفتار واقعی کاربران؛ دقت ۹۹.۵۸٪ روی همین
  مجموعه است و روی داده واقعی می‌تواند کمتر باشد.
- مدل کوچک روی دستگاه هنوز همراه APK نیست؛ هیچ عددی برای دقت/زمان مدل ادعا نمی‌شود.
- بنچمارک ایندکس روی Node است، نه ART/اندروید؛ بنچمارک روی گوشی ۶GB قدم بعدی است.
- FST واقعی پیاده‌سازی نشده؛ فقط یک پروکسی رشته‌ای سنجیده شد.
- بسته‌های ۵۰/۱۰۰/۳۰۰MB ساخته نشدند چون نرخ Hit بعد از ~۲۰MB اشباع شد؛ عدد
  «۲۰MB = ۱۸.۳۴MB واقعی» اندازه‌گیری شده است.
